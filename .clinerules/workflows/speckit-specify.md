# /speckit-specify

1. Read `AGENTS.md`, the constitution, `docs/product/requirements.md`, and the relevant canonical requirement sections.
2. Inspect current implementation enough to describe current state; do not implement.
3. Create or update the active `specs/<id>/spec.md` using `.specify/templates/spec-template.md`.
4. Map material behavior to `REQ-...` IDs or approved product decisions.
5. Record ambiguity as `CLARIFICATION-NEEDED`; do not invent missing requirements.
6. Define explicit in-scope/out-of-scope boundaries and acceptance criteria.
7. End with the approval gate. Do not code.
