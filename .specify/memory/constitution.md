# IntelliTrack Constitution

## I. Requirements before implementation
Approved requirement IDs in `02_core_requirements.md` are the primary functional scope. Existing code is not a requirement. Conflicts must be surfaced.

## II. Four business roles plus one technical role
Intern, Company Supervisor, Company Representative, and School Coordinator are the normal business roles. System Administrator remains technical/bootstrap/emergency.

## III. Simplicity over feature accumulation
Prefer removing, merging, or simplifying UI and workflows when the same requirements can be satisfied with less cognitive load.

## IV. Least privilege
Authorization boundaries are product requirements. A convenient UI shortcut must never broaden data scope or authority.

## V. Evidence and truthfulness
Do not fabricate operational data, AI findings, verification states, notifications, or metrics. AI output must be grounded and labeled.

## VI. Data and migration safety
Preserve operational data. Applied migrations are immutable. Migration/deployment actions require explicit approval.

## VII. Inspect, plan, verify, converge
Material changes follow: inspect -> specify -> clarify -> plan -> tasks -> approval -> implement -> verify -> converge.

## VIII. Human product authority
The agent may recommend. The human approves scope changes, role-authority changes, requirement interpretations, migrations, major IA redesigns, and deployment.

## Governance
`AGENTS.md` contains operational rules. This constitution defines the principles all specs and plans must satisfy. Amendments require an explicit product decision.
