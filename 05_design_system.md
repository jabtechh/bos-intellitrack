Good. We should plan design_system.md before creating it, and the main objective should be:

A warm, operational, distinctly branded internal tool—not a generic AI dashboard.

The common “AI-generated UI” look usually comes from repeating the same patterns:

oversized gradient hero sections

glowing purple or blue accents

glassmorphism everywhere

floating cards with excessive rounding

meaningless KPI cards

generic “Welcome back” dashboards

excessive sparkle icons

uniform card grids with no hierarchy

too much empty space

AI features visually dominating the product

We should deliberately avoid those patterns.

Proposed design_system.md Plan
1. Design Direction
Working design concept:

Coffeehouse Operations
The system should feel like a professional internal operations platform influenced by a modern coffeehouse environment.

Design qualities:

grounded

warm

structured

practical

human

calm

data-readable

brand-aware without looking promotional

The interface should resemble an internal workplace system—not an online coffee shop, marketing website, or AI startup dashboard.

2. Visual Identity Principles
The document should establish these principles:

Operational first
The UI prioritizes attendance, tasks, logs, reviews, and progress rather than decoration.

Brand influence, not brand imitation
Coffee-inspired colors and materials can influence the interface, but the system should not copy Bo’s Coffee’s official assets unless you have permission.

Dense but readable
Dashboards should show useful information without placing everything in isolated oversized cards.

AI stays secondary
AI-generated insights should appear within existing workflows rather than as a glowing chatbot-style feature.

Consistent hierarchy
Page titles, section labels, tables, actions, and status indicators should have predictable visual weight.

3. Proposed Color Direction
Rather than using plain brown everywhere, use a structured palette with warm neutrals and one distinctive accent.

Brand Core
Token	Color	Use
brand-900	#3A2418	Sidebar, strongest brand surfaces
brand-800	#4A2E20	Primary dark controls
brand-700	#62412E	Primary buttons
brand-600	#79543D	Hover and active states
brand-500	#956E52	Secondary accents
brand-300	#C6A98E	Muted indicators
brand-100	#EDE1D5	Soft selected states
brand-50	#F7F1EB	Brand-tinted background
This palette is less generic than a simple #5C3A21 brown and gives enough shades for real interface states.

Warm Neutral Palette
Token	Color	Use

Using warm grays instead of generic slate colors will make the interface feel intentional.

Distinctive Accent
A muted roasted-orange accent would give the system identity without looking playful:

Token	Color	Use

4. Semantic Colors
Status colors should remain familiar but slightly muted so they fit the warm palette.

Meaning	Strong	Soft background

5. Color Distribution Rule
A practical distribution rule can prevent the UI from becoming overly brown:

70% warm neutrals
20% brand browns
10% accent and semantic colors
Examples:

Main background: warm neutral

Cards and tables: white or cream

Sidebar: dark brand brown

Primary actions: medium brand brown

Active markers: roasted orange

Statuses: semantic colors

6. Layout Identity
To avoid the standard AI dashboard look, the design should not rely on endless card grids.

Instead, use:

strong page headers

sectional dividers

compact summary strips

operational tables

timeline rows

grouped information panels

narrow status columns

meaningful empty states

contextual side panels

For example, an attendance dashboard could use:

Page header
────────────────────────────────────
Today’s attendance summary strip
────────────────────────────────────
Main attendance table        Activity rail
Main attendance table        Pending actions
Main attendance table        Recent corrections
This is more distinctive and useful than six identical statistic cards.

7. Shape Language
To prevent the “AI template” look:

Cards: 8px–10px radius

Buttons: 6px–8px radius

Inputs: 6px radius

Badges: fully rounded only for compact statuses

Dialogs: 12px radius

Avoid 20px+ rounded cards

Avoid pill-shaped controls for everything

Avoid excessive shadows

Borders should do most of the separation work.

Recommended shadow:

box-shadow: 0 1px 2px rgba(38, 33, 29, 0.06);
Use stronger shadows only for menus, dialogs, and overlays.

8. Typography Direction
A strong anti-generic choice would be:

Headings: Source Serif 4 or Lora

Interface/body: Inter or Geist

Numbers/data: tabular numerals from the body font

Using a restrained serif for page titles would give the product a subtle coffeehouse/editorial character without reducing usability.

Suggested pairing:

Headings: Source Serif 4
Interface: Inter
Usage:

Serif only for page titles, major section headings, and selected report headings

Sans serif for forms, navigation, tables, buttons, and metrics

This would make IntelliTrack more recognizable than an all-Geist dashboard.

9. Component Character
The design system should define distinctive components such as:

Shift Status Strip
A horizontal operational summary showing:

current attendance status

time in

location verification

shift duration

primary action

Activity Ledger

Review Stamp

Progress Rail

Insight Note

no sparkle overload

10. Chart Design
Charts should feel like internal reports.

Rules:

no gradients

no rainbow palettes

no 3D charts

no decorative animation

gridlines should be subtle

chart labels should be visible

use direct labels where possible

maximum of five series

primary series uses roasted orange or brand brown

secondary series use muted blue, green, and neutral brown

Charts should answer a specific operational question, such as:

Are interns consistently completing required hours?

Which tasks are delayed?

How is attendance changing weekly?

What skill categories appear most often?

I suggest not including dark mode in the first design-system version.

A carefully designed light theme is more valuable than two incomplete themes, and internal administrative systems are commonly used in bright office environments.

Dark mode can be documented as a future enhancement.

IntelliTrack Design System
1. Document Purpose
This document defines the visual design language and reusable interface standards for IntelliTrack, the internship management system developed for a Bo’s Coffee context.

The design system serves as the single source of truth for:

color usage

typography

spacing

layout

component styling

responsive behavior

accessibility

data visualization

AI-assisted interface patterns

Tailwind CSS and shadcn/ui customization

The goal is to create a system that feels warm, structured, practical, and brand-aware without resembling a generic AI-generated dashboard.

2. Design Direction
2.1 Working Concept
Coffeehouse Operations

The interface should feel like a professional internal operations platform influenced by a modern coffeehouse environment.

It should feel:

warm

grounded

calm

structured

practical

human

data-readable

operational

It should not feel like:

an online coffee ordering app

a marketing website

a generic SaaS template

a futuristic AI dashboard

a glassmorphism concept

a neon productivity app

2.2 Core Principle
Operational clarity comes first. Brand character supports the interface but never interferes with usability.

3. Visual Identity Principles
3.1 Operational First
The interface prioritizes attendance, work logs, tasks, evaluations, documents, reports, and progress tracking.

Decorative elements must never compete with essential actions or status information.

3.2 Brand Influence, Not Brand Imitation
The system may use coffee-inspired colors, warm neutral surfaces, and subtle editorial typography.

The design must not directly reproduce official Bo’s Coffee visual assets unless authorized.

3.3 Dense but Readable
The UI should present useful information efficiently.

Avoid oversized cards and excessive empty space. Use:

summary strips

compact tables

grouped panels

timelines

ledgers

side rails

status columns

3.4 AI Is Secondary
AI-generated content should appear as part of an existing workflow.

AI features should not dominate the interface through:

glowing gradients

floating chatbot windows

neon borders

excessive sparkle icons

oversized assistant cards

3.5 Predictable Hierarchy
Page titles, section headings, tables, actions, filters, and statuses should maintain consistent visual weight and spacing.

4. Anti-Generic Design Rules
The following patterns are prohibited unless a specific use case requires them:

purple-blue gradients

glassmorphism

excessive drop shadows

floating card-only layouts

cards with very large rounded corners

oversized “Welcome back” hero sections

decorative AI sparkle effects

generic avatar clusters

rainbow charts

pill-shaped controls used everywhere

unnecessary animation

meaningless KPI cards

empty dashboards filled with decorative graphics

Preferred alternatives:

warm neutral surfaces

clear border-based separation

compact data groupings

functional side panels

information ledgers

structured timelines

contextual actions

restrained typography

flat, readable charts

5. Color System
5.1 Brand Color Palette
The brand palette uses deep roast brown tones for navigation, primary actions, and selected states.

Token	Hex	Recommended Use
brand-900	#3A2418	Main sidebar, strongest brand surface
brand-800	#4A2E20	Dark controls, active navigation
brand-700	#62412E	Primary buttons
brand-600	#79543D	Hover states
brand-500	#956E52	Secondary brand accents
brand-300	#C6A98E	Muted indicators
brand-100	#EDE1D5	Selected backgrounds
brand-50	#F7F1EB	Subtle brand-tinted surfaces
5.2 Warm Neutral Palette
Warm neutrals prevent the interface from feeling overly brown while keeping the visual language cohesive.

Token	Hex	Recommended Use
canvas	#F4F1EC	Main application background
surface	#FFFEFC	Cards, dialogs, tables
surface-muted	#ECE7E1	Secondary panels
border	#D8D1C8	Default borders
border-strong	#BEB4A8	Emphasized dividers
text-primary	#26211D	Main text
text-secondary	#675F58	Supporting text
text-muted	#8A8178	Metadata and captions
5.3 Accent Palette
The accent palette uses roasted orange to create identity without relying on common blue or purple SaaS colors.

Token	Hex	Recommended Use
accent-700	#9B4F24	Strong highlight
accent-600	#B65F2D	Active accent
accent-500	#C8743B	Progress indicators
accent-100	#F3D7C4	Soft accent background
Use accent colors sparingly for:

progress states

current-day markers

highlighted analytics

active chart series

non-critical attention states

5.4 Semantic Colors
Meaning	Foreground	Soft Background
Success	#34785A	#E3F0E9
Warning	#A66A15	#F7E9CC
Error	#A9433F	#F5DFDD
Information	#416C83	#DDEAF0
Pending	#806B51	#EEE7DC
Semantic colors must always be paired with text or icons.

Color must never be the only way to communicate state.

5.5 Color Distribution Rule
Use the following balance:

70% warm neutrals
20% brand browns
10% accent and semantic colors
Typical distribution:

application background: warm neutral

cards and tables: white or cream

sidebar: dark brand brown

primary actions: medium brand brown

active markers: roasted orange

statuses: semantic colors

5.6 Color Accessibility
All text and interactive states should meet WCAG AA contrast requirements.

Minimum targets:

body text: 4.5:1

large text: 3:1

UI boundaries and states: 3:1 where applicable

Do not place small text directly on accent-500 or brand-500 unless contrast is verified.

6. Typography
6.1 Font Pairing
Recommended pairing:

Headings: Source Serif 4

Interface and body: Inter

Fallback stack:

--font-heading: "Source Serif 4", Georgia, serif;
--font-body: Inter, ui-sans-serif, system-ui, sans-serif;

Label	Inter	14px	500
Caption	Inter	12px	400
Metric	Inter	28px	600
6.3 Typography Rules
Use serif typography only for:

page titles

major section headings

formal report headings

Use sans-serif typography for:

navigation

forms

tables

buttons

metrics

statuses

filters

metadata

Use tabular numerals for:

hours

dates

attendance times

percentages

counts

7. Spacing System
Use an 8px base spacing system.

Token	Value
space-1	4px
space-2	8px
space-3	12px
space-4	16px
space-5	24px
space-6	32px
space-7	40px
space-8	48px
space-9	64px
Recommended usage:

icon-to-label spacing: 8px

field label to input: 8px

related controls: 12px

card padding: 16px or 24px

section spacing: 32px

page section spacing: 40px to 48px

8. Shape and Elevation
8.1 Border Radius
Element	Radius
Inputs	6px
Buttons	6px to 8px
Cards	8px to 10px
Dialogs	12px
Status badges	Full radius
Tables	8px outer radius
Avoid:

20px or larger card radii

fully rounded large buttons

pill-shaped navigation tabs unless necessary

8.2 Shadows
Borders should provide most visual separation.

Default surface shadow:

box-shadow: 0 1px 2px rgba(38, 33, 29, 0.06);
Overlay shadow:

box-shadow: 0 8px 24px rgba(38, 33, 29, 0.12);
Use stronger shadows only for:

dialogs

menus

popovers

floating overlays

9. Layout System
9.1 Desktop Layout
Recommended desktop structure:

┌─────────────────────────────────────────────┐
│ Sidebar │ Top Bar                           │
│         ├───────────────────────────────────┤
│         │ Page Header                       │
│         │ Summary Strip                     │
│         │ Main Content        Context Rail  │
│         │ Main Content        Context Rail  │
└─────────────────────────────────────────────┘
9.2 Sidebar
Recommended sidebar properties:

background: brand-900

width: 248px

text: warm white

active item: brand-600

hover: translucent warm white

icon size: 18px

section labels: small uppercase or muted text

no heavy gradients

9.3 Page Header
Every page header should include:

page title

concise description

optional primary action

optional filters

optional metadata

Avoid large decorative welcome banners.

9.4 Content Structure
Prefer:

summary strips

split panels

structured data tables

timelines

progress rails

side panels

review queues

Avoid endless grids of identical cards.

10. Iconography
Use Lucide React.

Recommended default sizes:

navigation: 18px

buttons: 16px

empty states: 24px to 32px

inline status: 14px to 16px

Rules:

use outline icons

use consistent stroke weight

do not mix icon libraries

do not use emojis as interface icons

use sparkle icons only for explicitly AI-assisted content

11. Core Components
11.1 Buttons
Primary Button
background: brand-700

text: white

hover: brand-600

radius: 8px

height: 40px

Secondary Button
background: surface

border: border-strong

text: text-primary

hover: brand-50

Destructive Button
background: error foreground

text: white

Text Button
no filled background

use for tertiary actions

underline only on hover if appropriate

11.2 Inputs
Inputs should use:

white or surface

1px warm neutral border

6px radius

40px minimum height

visible focus ring

concise helper text

clear inline error message

Focus state:

outline: 2px solid #C8743B;
outline-offset: 2px;
11.3 Tables
Tables should prioritize scanability.

Recommended rules:

sticky header where useful

subtle row separators

compact row height

visible status column

right-align numeric values

avoid zebra striping unless data density requires it

show bulk actions only after row selection

11.4 Status Badges
Status badges may use full-radius shapes because they are compact status indicators.

Examples:

Present

Absent

Late

Pending

Approved

Rejected

Needs Revision

Badges must include readable text, not color alone.

11.5 Navigation
Active navigation should be clearly visible through:

background change

stronger text

active icon state

optional left indicator

Do not use glowing highlights.

11.6 Dialogs
Dialogs should include:

concise title

one clear purpose

visible close control

primary and secondary action

no excessive vertical padding

no decorative illustration unless useful

11.7 Empty States
Empty states should be:

compact

specific

actionable

context-aware

Avoid generic messages such as:

Nothing here yet.

Prefer:

No work logs have been submitted for this week.

11.8 AI Insight Note
AI-assisted content should appear as an analyst note.

Recommended structure:

AI-assisted insight
Generated from attendance and work-log data
────────────────────────────────────────────
Observation
Supporting evidence
Suggested next action
────────────────────────────────────────────
Generated on [date]
Styling rules:

neutral or soft warm background

small AI-assisted label

no neon gradients

no chat bubbles

no glowing border

no excessive sparkle icons

always identify generated content

12. Signature Components
These components give IntelliTrack its own visual identity.

12.1 Shift Status Strip
Displays:

current attendance state

time in

time out

shift duration

location verification

primary attendance action

Use a compact horizontal layout rather than multiple metric cards.

12.2 Activity Ledger
A chronological operational record used for:

attendance events

work-log submissions

approvals

corrections

evaluations

The ledger should use:

timestamp column

event label

responsible person

status

optional action

12.3 Review Stamp
Used for document and evaluation states.

Examples:

Approved

Needs Revision

Pending Review

Rejected

The style should resemble a restrained administrative stamp, not a decorative badge.

12.4 Progress Rail
Used to display internship progression:

Application → Onboarding → Active Internship → Evaluation → Completion
Prefer a horizontal or vertical rail instead of a circular progress chart.

12.5 Context Rail
A narrow right-side panel for:

pending actions

recent updates

deadlines

review reminders

quick status details

13. Data Visualization
13.1 Chart Principles
Charts should answer a clear operational question.

Examples:

Are interns completing required hours?

Which tasks are delayed?

How is attendance changing weekly?

Which skill categories appear most often?

13.2 Chart Rules
no gradients

no 3D charts

no rainbow colors

no decorative animations

maximum five series

use direct labels where possible

keep gridlines subtle

display units clearly

use semantic colors only when meaning is stable

13.3 Recommended Series Order
roasted orange

brand brown

muted green

muted blue

neutral brown-gray

14. Responsive Behavior
14.1 Breakpoints
Use Tailwind defaults unless implementation requires adjustment.

Recommended behavior:

mobile: stacked content, collapsible navigation

tablet: two-column content where appropriate

desktop: persistent sidebar and optional context rail

14.2 Mobile Rules
On mobile:

collapse sidebar into a drawer

place primary action near page title

stack summary strips vertically

convert wide tables into responsive lists or horizontal scroll only when necessary

keep touch targets at least 44px

avoid dense multi-column forms

15. Motion
Motion should be subtle and functional.

Recommended durations:

hover: 120ms

button state: 150ms

panel transition: 180ms

dialog transition: 200ms

Use motion for:

state changes

drawers

dialogs

menu appearance

loading progress

Do not use:

bouncing icons

floating cards

continuous animation

decorative parallax

glowing pulse effects

Respect prefers-reduced-motion.

16. Accessibility
The system should include:

keyboard navigation

visible focus states

semantic HTML

proper labels

accessible dialogs

descriptive button text

sufficient contrast

status text paired with color

alt text for meaningful images

reduced-motion support

Forms should show errors:

near the affected field

in clear language

without relying on color alone

18. shadcn/ui Customization Rules
Use shadcn/ui as a component foundation, not as the final visual identity.

Customize:

CSS variables

button radius

input radius

border colors

card padding

muted backgrounds

typography

table density

focus states

Do not retain the default black-and-white appearance unchanged.

Do not introduce components solely because they exist in the library.

Every component should support an actual IntelliTrack workflow.

19. Dark Mode
Dark mode is not part of the initial design-system release.

The first implementation should focus on a complete and accessible light theme.

Dark mode may be added later after:

the light theme is stable

all semantic states are verified

charts are tested

forms and tables are validated

contrast checks are completed

20. Design Review Checklist
Before approving a screen, confirm:

Does the screen support a clear operational task?

Is the hierarchy immediately understandable?

Are actions easy to find?

Is brown used intentionally rather than excessively?

Are semantic colors used correctly?

Is important information visible without opening multiple cards?

Does the screen avoid generic AI-dashboard patterns?

Are AI-generated outputs clearly labeled?

Are tables and forms readable?

Does the design work on mobile?

Are keyboard focus states visible?

Does the screen feel consistent with the rest of IntelliTrack?

21. Final Design Direction
The approved IntelliTrack visual direction is:

A warm operational interface with dark roast navigation, paper-like surfaces, restrained roasted-orange accents, compact data layouts, subtle editorial typography, and clearly structured workflows.

The design should feel custom, human, and practical rather than template-driven or visibly AI-generated.

no chat bubbles

no glowing border

no excessive sparkle icons

always identify generated content

These components give IntelliTrack its own visual identity.

12.1 Shift Status Strip
Displays:

current attendance state

shift duration

location verification

primary attendance action

12.2 Activity Ledger
A chronological operational record used for:

attendance events

approvals

timestamp column

12.3 Review Stamp
Used for document and evaluation states.

12.4 Progress Rail
Used to display internship progression:

Application → Onboarding → Active Internship → Evaluation → Completion

13. Data Visualization
13.1 Chart Principles
Charts should answer a clear operational question.

Examples:

Are interns completing required hours?

Which tasks are delayed?

How is attendance changing weekly?

Which skill categories appear most often?

13.2 Chart Rules
no gradients

no 3D charts

no rainbow colors

no decorative animations

maximum five series

use direct labels where possible

keep gridlines subtle

display units clearly

use semantic colors only when meaning is stable

13.3 Recommended Series Order
roasted orange

brand brown

muted green

muted blue

neutral brown-gray

14. Responsive Behavior
14.1 Breakpoints
Use Tailwind defaults unless implementation requires adjustment.

Recommended behavior:

mobile: stacked content, collapsible navigation

tablet: two-column content where appropriate

desktop: persistent sidebar and optional context rail

14.2 Mobile Rules
On mobile:

collapse sidebar into a drawer

place primary action near page title

stack summary strips vertically

convert wide tables into responsive lists or horizontal scroll only when necessary

keep touch targets at least 44px

avoid dense multi-column forms

15. Motion
Motion should be subtle and functional.

Recommended durations:

hover: 120ms

button state: 150ms

panel transition: 180ms

dialog transition: 200ms

Use motion for:

state changes

drawers

dialogs

menu appearance

loading progress

Do not use:

bouncing icons

floating cards

continuous animation

decorative parallax

glowing pulse effects

Respect prefers-reduced-motion.

16. Accessibility
The system should include:

keyboard navigation

visible focus states

semantic HTML

proper labels

accessible dialogs

descriptive button text

sufficient contrast

status text paired with color

alt text for meaningful images

reduced-motion support

Forms should show errors:

near the affected field

in clear language

without relying on color alone

18. shadcn/ui Customization Rules
Use shadcn/ui as a component foundation, not as the final visual identity.

Customize:

CSS variables

button radius

input radius

border colors

card padding

muted backgrounds

typography

table density

focus states

Do not retain the default black-and-white appearance unchanged.

Do not introduce components solely because they exist in the library.

Every component should support an actual IntelliTrack workflow.

19. Dark Mode
Dark mode is not part of the initial design-system release.

The first implementation should focus on a complete and accessible light theme.

Dark mode may be added later after:

the light theme is stable

all semantic states are verified

charts are tested

forms and tables are validated

contrast checks are completed

20. Design Review Checklist
Before approving a screen, confirm:

Does the screen support a clear operational task?

Is the hierarchy immediately understandable?

Are actions easy to find?

Is brown used intentionally rather than excessively?

Are semantic colors used correctly?

Is important information visible without opening multiple cards?

Does the screen avoid generic AI-dashboard patterns?

Are AI-generated outputs clearly labeled?

Are tables and forms readable?

Does the design work on mobile?

Are keyboard focus states visible?

Does the screen feel consistent with the rest of IntelliTrack?

21. Final Design Direction
The approved IntelliTrack visual direction is:

A warm operational interface with dark roast navigation, paper-like surfaces, restrained roasted-orange accents, compact data layouts, subtle editorial typography, and clearly structured workflows.

The design should feel custom, human, and practical rather than template-driven or visibly AI-generated.
